# Data Request Checklist

**Stage:** 2 · Foundation — the gate before any advice
**Source:** Dan Packard §2.1(a) — primary (M&A catalog is the base artifact)
**Version:** v0.1 SCAFFOLD — deep-drafted; core lists functional, engagement-specific refinements pending extraction.

## What it does

Turns "we're starting an engagement" into a complete, client-ready document request in minutes. The audit found 25–30% of every advisory engagement is invisible cleanup the client didn't know they bought — a sharp request list up front is the cheapest way to shrink that number.

## Inputs

- Engagement type: advisory / valuation / M&A (buy-side or sell-side) / tax planning / forensic
- Service tier if known (Gold / Silver / Bronze) and catalog phase
- What already exists in the war room (never re-request what the client already sent)
- Entity structure and industry, if known

## Process

1. Check the war room first. Anything already on file gets marked "have — verify current" instead of requested.
2. Build the base list for the engagement type (below).
3. Add tier- and phase-specific items from the service catalog `[EXTRACT: the 10-phase catalog's per-phase document requirements]`.
4. Sequence it: what's needed in week one vs. what can follow. Flag the items that gate the Five-Year Normalizer (financials) and the Smell-Test.
5. Output a client-ready request letter section plus an internal tracking table (item · why we need it · gates what · status).

## Base lists (v0.1 — drawn from the workflow map's data dependencies; refine in extraction)

**Every engagement:** 3–5 years financial statements (P&L, balance sheet, cash flow) · 3 years business tax returns · current-year interim financials · QuickBooks/GL access or export · org chart and entity diagram · ownership table.

**Advisory / classification:** owner compensation detail and personal expenses run through the business · debt schedules and personal guarantees · key customer concentration data · management team roster and comp.

**Valuation:** fixed asset register · inventory detail · lease agreements · related-party transaction detail · prior valuations if any.

**M&A sell-side:** customer contracts · supplier agreements · employee census · IP and licenses · pending litigation summary · add-back documentation for normalization.

**Forensic / tracing:** complete bank and credit card statements for the tracing period (every account) · loan documents · wire records · accounting system audit trail.

**Tax:** prior 3 years returns all entities · current-year projections · fixed asset / depreciation schedules · state filings footprint.

## Output

Two artifacts: (1) a client-facing request list in plain language, grouped and sequenced, ready to paste into the engagement letter package or ShareFile request; (2) the internal gating table showing which downstream skills each item unblocks.

## Guardrails

- Never send a kitchen-sink list. Everything requested must trace to a named engagement need — the skill states the "why" per item so the client sees purpose, not burden.
- Missing-item follow-ups route through Proactive Client Follow-Up, not ad hoc emails.
