# Cooper Norman Skill Library — Build Repository

Phase 2 build under the Consulting Services Agreement (v7). 25 skills mapped from the Phase 1 audit; agreement ceiling is 35. Four Methodology Builds are the scope boundary: §2.1(a) Dan Packard, §2.1(b) Eric Story, §2.1(c) Scott Nielson, §2.1(d) Daniel Hopkins.

## How this library is built

Every skill ships as a folder with a `SKILL.md` and, where needed, bundled references. Skills are written against the seven-stage advisory spine from the Current-State Workflow Map: 1 Trigger · 2 Foundation · 3 Diagnostic Discovery · 4 The Pivot · 5 The Branch · 6 The Conversation · 7 Sticky Relationship.

## Versioning and the extraction convention

- **v0.1 — SCAFFOLD.** Structure, triggers, inputs/outputs, and guardrails are real. Methodology content is drawn only from Phase 1 audit artifacts (discovery interviews, workflow map, firm artifacts referenced there). Anything that must come out of a source's head is marked `[EXTRACT: ...]`.
- **v0.5 — EXTRACTED.** The `[EXTRACT]` blocks are filled from working sessions with the named primary source (or contributing practitioners, per §2.1). No unmarked invention permitted: if it isn't from a session, an artifact, or a reviewed draft, it doesn't go in.
- **v1.0 — VALIDATED.** Tested against at least one live or historical engagement with the source and accepted.

**The rule that governs everything here:** a skill never claims Cooper Norman methodology it does not have. Second-hand methodology is disclosed as such (§2.1 protective clause). The `[EXTRACT]` markers are the honest boundary between what the audit captured and what the sessions must produce.

Each SKILL.md ends with an **Extraction session agenda** — the specific questions that convert the scaffold to v0.5. These double as the working-session run sheets.

## Guardrails that apply library-wide

1. **Partner gate (all skills):** every output is a draft for professional review. No skill concludes, advises the client directly, or files anything.
2. **Tax skills surface, never conclude** (§2.1(c) skills carry this in their own guardrails, verbatim from the Skill Library commitment).
3. **Client data stays in the war room.** Skills reference the client project's files and memory; they do not move data outside the engagement workspace.
4. **Numbers tie out.** Any extracted or normalized figure must reconcile to source documents; discrepancies are flagged, not smoothed.
